# 产品测试 — 2026 年 9 月 10 日

[English](PRODUCT_TESTS.md) | 简体中文

MCP Lens rc.10 修复了一个多步工具调用问题：服务器同时返回文字摘要和结构化
数据时，模型能读到摘要，却看不到下一步需要的客户 ID。现在 Lens 会一起呈现
两者；如果文字本身已包含相同 JSON，就不再重复添加。

## 模型执行的任务

每个任务使用一个新的 Codex agent、Harness `0.1.2-rc.1` 和相同的两个本地
MCP 服务器，共 16 个工具。模型自行选择工具和参数，测试根据实际返回的 ID、
金额、状态和调用顺序检查结果。

| 任务 | 官方 MCP 客户端 | MCP Lens rc.10 |
|---|---|---|
| 根据中文请求查找登录工单 | 完成 | 完成 |
| 查客户 → 最新订单 → 配送状态及金额 | 停止：可见结果中缺少客户 ID | 完成 |
| 健康检查超时后恢复查询客户 | 完成 | 完成 |

修复前的 Lens 在结构化数据任务上也会停止。修复后，模型拿到了客户 ID，
将其传给订单查询，再返回准确的订单 ID、配送状态、金额和币种。

工单任务和超时任务各增加一次搜索，三步订单任务增加两次搜索。本轮使用模拟
业务数据和 Codex；之前的 DeepSeek 模型测量见 [8 月 14 日报告](LIVE_DEEPSEEK_PILOT.zh-CN.md)。

## 数据流程测试

在 16 和 1,000 个工具下分别运行六个任务：客户查询、退款工单、登录工单、
普通订单查询、结构化订单查询和超时恢复。修复前后使用相同的脚本和服务器数据。

| 版本 | 官方 MCP 客户端 | MCP Lens |
|---|---:|---:|
| 修复前 | 10/12 | 10/12 |
| 修复后 | 10/12 | 12/12 |

改善的两项分别是两种工具规模下的结构化订单任务。这个脚本检查数据传递，
不让模型选择工具。

## 回归检查

- 类型检查、构建和 178 项测试通过。
- 原有 12 个搜索查询的排序保持一致。
- 1,000 个远程工具下，Lens 仍只呈现 2 个 Schema，共 1,114 UTF-8 bytes。
- 打包后的插件在 Harness `0.1.2-rc.1` 安装成功，并通过搜索、调用和禁止调用检查。
- 更新后的本地 Web Profile 启动成功，并通过官方公开 MCP 文档服务器搜索和读取
  Streamable HTTP 文档。
